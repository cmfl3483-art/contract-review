# 腾讯云部署与域名迁移经验沉淀

## 1. 钉钉登录 MultipleRowsFound 错误修复

**背景**：钉钉 OAuth 登录报错 `Multiple rows were found when one or none was required`

**原因**：数据库中存在两条相同 `dingtalk_union_id` 的用户记录（赵迎春），`scalar_one_or_none()` 遇到多行数据抛出异常

**解决**：
1. SQL 合并重复记录，更新外键后删除重复行
2. 在 `sync_user_info()` 方法中对 `dingtalk_union_id` 和 `dingtalk_user_id` 查询添加 `.limit(1)` 做防御性编码

```python
stmt = select(User).where(User.dingtalk_union_id == union_id).limit(1)
```

**要点**：`scalar_one_or_none()` 不会自动限制查询行数，对于可能存在重复数据的字段，务必手动加 `limit(1)` 保护。

## 2. Docker 生产部署与优化

**背景**：将项目从本地 Docker 部署到腾讯云服务器（124.222.219.177）

### 2.1 Dockerfile 优化（慢网络环境）

```dockerfile
FROM python:3.11-slim
RUN sed -i 's|deb.debian.org|mirrors.tencent.com|g' /etc/apt/sources.list.d/debian.sources
RUN pip install -i https://mirrors.tencent.com/pypi/simple/ -r requirements.txt
```

关键优化点：
- apt 源切换为腾讯云镜像
- pip 源切换为腾讯云镜像
- 移除 gcc、postgresql-client 等不必要的包
- 设置 `PIP_DEFAULT_TIMEOUT=300` 避免超时

### 2.2 docker-compose.yml 生产配置差异

与本地开发环境的区别：
- 前端端口绑定 `127.0.0.1:8080:80`（由宿主 Nginx 反代，避免端口冲突）
- 注释掉 `./backend:/app` volume 挂载（使用镜像内代码而非本地目录）
- 新增 celery_worker 和 frontend 的 healthcheck
- DINGTALK_REDIRECT_URI 和 CORS_ORIGINS 配置为生产域名

### 2.3 healthcheck 配置参考

```yaml
# celery_worker 健康检查
celery_worker:
  healthcheck:
    test: ["CMD-SHELL", "celery -A app.celery_app inspect ping -d celery@$$HOSTNAME || exit 1"]
    interval: 30s
    timeout: 10s
    retries: 3
    start_period: 30s

# frontend 健康检查
frontend:
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost/"]
    interval: 30s
    timeout: 10s
    retries: 3
    start_period: 10s
```

**要点**：生产环境建议使用 `docker-compose.prod.yml` 独立配置，与本地开发隔离。

## 3. 数据库迁移与数据迁移

### 3.1 新数据库需执行 Alembic 迁移

**背景**：服务器上的 PostgreSQL 是空库，访问报 `relation "contracts" does not exist`

**解决**：
```bash
docker compose exec backend alembic upgrade head
```

### 3.2 数据导出导入（pg_dump）

**背景**：需要将本地数据库数据迁移到服务器

**操作**：
```bash
# 导出（加 --clean --if-exists 避免导入时索引/约束冲突）
docker exec contract_review_postgres pg_dump -U postgres -d contract_review \
  --no-owner --no-privileges --clean --if-exists > dump.sql

# 导入
scp dump.sql ubuntu@server:/tmp/
docker compose exec -T postgres psql -U postgres -d contract_review < /tmp/dump.sql
```

**要点**：`pg_dump` 导出务必加 `--clean --if-exists`，否则 `Alembic` 已创建的表结构会导致数据导入跳过。

### 3.3 MinIO 附件迁移

```bash
# 本地导出
docker exec contract_review_minio mc mirror local/contract-attachments /tmp/minio-export
docker cp contract_review_minio:/tmp/minio-export /tmp/minio-data

# 传到服务器导入
tar czf minio-data.tar.gz minio-data/
scp minio-data.tar.gz ubuntu@server:/tmp/
docker cp /tmp/minio-data/. contract_review_minio:/data/contract-attachments/
```

## 4. Nginx 反向代理架构

**部署架构**：宿主机 Nginx（80/443）→ Docker 服务（127.0.0.1:8080/8000）

```
用户 → 域名:443 → 宿主机 Nginx → 前端 127.0.0.1:8080
                              → 后端 127.0.0.1:8000/api/
```

**关键配置**：
```nginx
server {
    listen 443 ssl;
    server_name chenmin.yunumall.com;
    
    location / {
        proxy_pass http://127.0.0.1:8080;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
    }
    client_max_body_size 50M;
}
```

**要点**：Docker 前端容器绑定 `127.0.0.1:8080` 而不是 `80:80`，避免与宿主机 Nginx 端口冲突。

## 5. SSL 证书（Let's Encrypt）

### 5.1 首次申请
```bash
sudo certbot certonly --nginx -d chenmin.yunumall.com
```

### 5.2 域名切换后更新证书
```bash
# 为新域名申请证书
sudo certbot certonly --nginx -d new-domain.com --non-interactive --agree-tos -m admin@domain.com

# 更新 Nginx 配置中的证书路径
sudo sed -i 's|/etc/letsencrypt/live/old-domain|/etc/letsencrypt/live/new-domain|g' /etc/nginx/sites-available/config
sudo nginx -t && sudo systemctl reload nginx
```

**要点**：Let's Encrypt 证书绑定域名，更换域名时必须重新申请证书。证书存储在服务器本地 `/etc/letsencrypt/live/`，自动续期。

## 6. DNS 解析与 ICP 备案

### 6.1 DNS 迁移流程

```
Cloudflare DNS → 腾讯云 DNSPod
```

步骤：
1. 在腾讯云 DNSPod 添加 A 记录：`@ → 124.222.219.177`
2. 在域名注册商处将 NS 修改为腾讯云的：`f1g1ns1.dnspod.net`
3. 等待 NS 记录全球生效（几分钟到几小时）

### 6.2 腾讯云境内服务器 ICP 备案强制要求

**问题**：同事无法访问域名，提示 `ERR_CONNECTION_RESET`，HTTP 访问显示"网站未完成备案"

**原因**：腾讯云中国境内服务器强制要求域名完成 ICP 备案，未备案域名会被拦截

**要点**：
- ICP 备案按一级域名主体管理，子域名依附于父域名
- 备案期间不需要网站可正常访问
- 备案前域名必须先完成实名认证
- 备案审核周期约 7-20 个工作日
- 使用已备案的二级域名（如 `app.yunumall.com` 的 `yunumall.com` 已备案）可以直接使用

### 6.3 Cloudflare Proxy vs DNS Only

| 方式 | 优点 | 缺点 |
|------|------|------|
| **DNS Only（灰色云）** | 国内直连，上传速度快 | 必须 ICP 备案 |
| **Proxy（橙色云）** | 可绕过备案拦截 | 流量绕海外，上传慢 |
| **已备案域名** | 国内直连 + 正常访问 | 需提交备案资料 |

## 7. 钉钉 OAuth 回调配置

### 7.1 回调域名格式

钉钉开放平台「安全设置 → 重定向URL（回调域名）」中填写**完整 URL**：

```
https://chenmin.yunumall.com/api/auth/dingtalk/callback
```

### 7.2 修改后需三方一致

当更换域名时，确保以下三处同时更新：
1. `docker-compose.yml` / `docker-compose.prod.yml` 中的 `DINGTALK_REDIRECT_URI`
2. Nginx 配置中的 `server_name`
3. 钉钉开放平台的安全设置

### 7.3 钉钉开放平台缓存问题

修改回调域名后如果仍报错，尝试**删除旧记录 → 保存 → 重新添加 → 保存**，钉钉平台可能存在配置缓存。

## 9. 生产环境差异化配置最佳实践

推荐使用多文件策略：
- `docker-compose.yml` — 本地开发（volume 挂载、热重载）
- `docker-compose.prod.yml` — 生产部署（镜像内代码、healthcheck、域名配置）

```bash
# 生产环境启动
docker compose -f docker-compose.prod.yml up -d --build

# 生产环境重启单个服务
docker compose -f docker-compose.prod.yml up -d backend
```
